# 배포 전 보안 점검

점검일 2026-11-27

## 먼저 처리할 3가지

1. **GitHub에 올리기 전 설정 파일 보호 규칙을 만든다.** 현재 폴더에서 `.gitignore`가 발견되지 않았다. 비밀 설정 파일이 앞으로 실수로 업로드되지 않도록 규칙을 설정한다.
2. **사용 중인 GitHub 저장소와 과거 이력을 확인한다.** 현재 폴더는 Git 저장소가 아니며 연결된 원격 저장소도 확인되지 않았다. GitHub에 이전에 업로드된 파일이나 삭제된 파일의 이력은 확인 필요다.
3. **로그인과 데이터 저장 방식을 정한 뒤 접근 권한을 점검한다.** 현재 시안에서 로그인과 데이터베이스 연결 코드는 발견되지 않았다. 추후 추가할 때 다른 사람의 자료를 볼 수 없고 관리자만 수정할 수 있는지 검증한다.

위 순서는 앞으로 배포와 기능 추가를 진행한다는 계획에 따른 우선순위다. 현재 비밀키 유출이나 권한 침해가 발생했다는 뜻은 아니다.

## 점검 범위

현재 작업 폴더의 `docs/PRD.md`, `docs/ACCEPTANCE.md`, `docs/FINANCIAL_RESEARCH.md`, `docs/dashboard-preview.html`, `data/financials.json`을 확인했다. HTML 시안의 최신 저장본과 프로젝트 폴더의 파일을 대상으로 흔한 비밀값 형태 및 로그인·데이터 연결 코드를 확인했다. 자동 검색은 모든 형태의 비밀값을 찾아내지는 못한다. GitHub 저장소 주소, 데이터베이스 관리자 화면, 배포 설정은 제공되지 않아 직접 확인하지 못했다.

## 용어 설명

- **API 키**는 외부 서비스 사용자를 구별하는 값이다. 비밀 키는 다른 사람이 사용하지 못하도록 보호해야 한다.
- **.env**는 서비스 접속 정보 등을 보관하는 설정 파일이다.
- **.gitignore**는 Git이 새로 추적하지 않을 파일을 정하는 목록이다. 이미 올라간 파일의 과거 기록은 별도로 확인해야 한다.
- **Git 이력**은 코드가 이전에 어떻게 바뀌었는지 기록한 내역이다.
- **service_role 키**는 Supabase에서 높은 권한을 가진 비밀 키다. 브라우저에 넣으면 방문자가 확인할 수 있다.
- **RLS**는 데이터베이스의 행 단위 접근 규칙으로, 사용자마다 읽거나 수정할 수 있는 자료를 제한한다.
- **입력 검증**은 사용자가 보낸 값이 허용된 형태인지 확인하는 과정이다.

## 남은 확인

이 보고서는 발견된 파일과 제공된 정보에 한정된다. GitHub 저장소의 과거 이력, 실제 로그인·데이터베이스 설정, 외부 서비스의 과금 한도는 확인 필요다. 코드와 설정은 이번 점검에서 변경하지 않았다.
